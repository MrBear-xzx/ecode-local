# Ecode Local

用于泛微 E-cology 9 Ecode 本地开发的 VS Code 扩展，提供多环境隔离、安全同步、跨环境变更集和 Ecode 代码智能。

## 安装与升级

从 GitHub Releases 下载 `.vsix`，在 VS Code 扩展视图选择“从 VSIX 安装”，安装后重新加载窗口，并核对版本号和 Release 提供的 SHA-256。

0.6 不兼容 0.5 及以下项目，也不自动迁移旧数据。检测到旧版 `ecode/`、`.ecode-ai/`、`.ecode-local/storage/` 或旧工作区配置时，扩展会阻止运行。请先用旧版完成同步和备份，清理旧项目后再安装 0.6，重新配置环境并分别全量拉取。

## 环境与存储

环境不区分测试或正式，任意环境都可作为变更集来源或目标。每个环境配置：

1. 环境名称；
2. 环境目录；
3. E-cology 服务器地址；
4. 登录名；
5. 密码。

环境目录位于工作区根目录，只允许英文字母、数字和下划线，且创建后不可修改。`common` 和 `promotion` 是保留名称。

```text
workspace/
├─ dev_env/                         # 环境源码
├─ prod_env/
└─ .ecode-local/
   ├─ environments.json             # 环境配置
   ├─ dev_env/                      # 清单、快照、冲突、恢复和项目知识
   ├─ prod_env/
   ├─ common/ecode-ai/              # 公共 API/组件知识
   └─ promotion/                    # 推送、变更集和应用记录
```

切换环境只切换活动源码目录及其独立状态，不复制或覆盖文件。环境配置保存在 `.ecode-local/environments.json`；密码和 Cookie 按环境 ID 保存在 VS Code `SecretStorage`，不会写入工作区或日志。`.ecode-local/` 可能包含源码快照，不应提交到版本库。

## 日常使用

首次使用：

1. 执行 `Ecode: 配置当前环境`；
2. 填写环境信息并通过连接测试；
3. 执行 `Ecode: 全量拉取`；
4. 新增其他环境，并分别完成一次全量拉取。

未建立同步基线的环境不会把现有源码误报为新增，也不能推送或应用变更集。

日常同步：

1. 在当前环境目录编辑源码；
2. 等待自动刷新，或执行 `Ecode: 刷新本地变更`；
3. 检查差异并执行 `Ecode: 选择并推送`；选择文件后会直接执行，推送记录默认使用当前时间命名；
4. 推送成功后从环境节点的“推送记录”查看文件差异、重命名或删除记录，也可对单个文件执行本地回退。

推送前会检查最新远端状态、JavaScript/JSX 编译结果和 GBK 可表示性，写入后回读校验。更新请求超时或返回 5xx 时会先回读远端再判断实际结果；已落地的相同内容可在再次确认后补齐基线和推送记录，不重复上传。

手动推送选择文件后不再额外弹框确认。通过 AI 请求发起的推送仍保留人工确认，避免后台请求未经确认直接修改远端。

Ecode 可能返回无法直接改名或删除的重名节点。相同路径且节点 ID 相同时，扩展会安全去重；节点 ID 不同时，会优先选择唯一有数据的文件或目录。若仍无法唯一判断，扩展只把具体文件或目录子树标记为“远端歧义/不支持”，保留该子树已有的本地文件并继续拉取其他安全文件；推送和变更集应用不会写入歧义路径。输出日志会记录冲突路径和脱敏后的候选节点 ID，便于排查。不同目录中的同名项不受影响。

GBK 不支持的字符必须改用 ASCII 转义，例如 `›`（U+203A）写成 `"\u203A"`；普通 ASCII `>` 不受影响。

推送记录中的文件回退只修改本地源码，不修改远端或同步基线；如果文件在推送后又被编辑，扩展不会覆盖新编辑。

## 跨环境变更集

变更集不依赖 Git，也不绑定目标环境：

1. 在来源环境完成推送；
2. 执行 `Ecode: 创建跨环境变更集`，选择一次或多次推送记录；
3. 展开变更集检查文件和具体差异；
4. 切换目标环境，点击“应用到当前环境”；
5. 在确认弹框中确认应用。

变更集实际写入目标环境的文件会同时保存为该环境的一条推送记录，默认名称与变更集名称一致，并以目标环境写入前后的真实内容生成差异和回退快照。没有产生实际写入的幂等文件不会重复计入推送记录。

同一文件的多次推送会折叠为最终净变化。变更集保存完整文件快照，不做分支或逐行合并：

- 新增或修改：按相同相对路径创建或覆盖为最终快照；
- 删除：删除目标环境同路径文件；
- 覆盖或删除前，分别保存目标远端和本地的不同内容；
- 文件/目录同名、父路径是文件、不安全路径或 GBK 不兼容会阻止整单写入；
- 写入后回读校验并更新目标环境源码、基线和应用记录；
- 重复应用会收敛已成功文件，并继续处理未完成文件。

Ecode 服务端不提供事务，网络或服务端错误仍可能导致部分成功。

点击变更集右侧的“取消变更集”只删除变更集记录，不删除推送或应用记录，也不回退任何本地或远端代码。

## 冲突与恢复

普通拉取和推送不会静默覆盖两侧修改。冲突可选择接受最新远端，或确认已经手工合并并保留本地。

恢复副本保存在：

```text
.ecode-local/<环境目录>/recovery/
```

## 代码智能与 AI

扩展提供 Ecode API、表单字段、`ecCom/antd` 组件以及静态 `ecodeSDK.setCom/getCom` 的补全、悬停和跳转。组件定义和引用按当前文件所属环境隔离。

AI 知识分为：

- `.ecode-local/common/ecode-ai/`：公共 API 和组件知识；
- `.ecode-local/<环境目录>/ecode-ai/`：环境组件关系和表单元数据；
- `AGENTS.md`：当前环境入口和安全约束。

AI 只有在用户明确授权推送时才能创建 `.ecode-local/ai-requests/<id>.json`。扩展仍会校验环境和文件、弹出人工确认，并把结果写入 `.ecode-local/ai-results/<id>.json`；AI 不能绕过扩展直接调用远端接口。

## 常用命令

| 命令 | 作用 |
| --- | --- |
| `Ecode: 配置当前环境` | 编辑环境连接 |
| `Ecode: 新增环境` | 新增独立环境 |
| `Ecode: 切换环境` | 切换活动环境 |
| `Ecode: 全量拉取` | 建立或刷新同步基线 |
| `Ecode: 刷新本地变更` | 扫描当前环境 |
| `Ecode: 选择并推送` | 推送选中文件 |
| `Ecode: 创建跨环境变更集` | 从推送记录创建变更集 |
| `Ecode: 应用变更集到当前环境` | 应用最终文件快照 |
| `Ecode: 取消变更集` | 删除变更集记录 |
| `Ecode: 刷新 AI Coding 支持` | 刷新公共和环境知识 |

## 开发与兼容

```bash
npm run build
npx tsc --noEmit
npm test
```

使用现有 `package-lock.json` 和 npm 工作流。当前没有 ESLint 配置，`npm run lint` 不能作为有效验证。

兼容 VS Code 1.93+、泛微 E-cology 9 Ecode 和 0.6 项目格式；JavaScript/JSX 编译行为以 Ecode Babel 7.5.5 为准。
