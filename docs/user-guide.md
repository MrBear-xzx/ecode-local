# Ecode Local 使用指南

本文补充 README 中未展开的操作规则和异常处理。首次使用建议先阅读 [快速开始](../README.md#快速开始)。

## 环境与本地数据

环境不区分测试或正式，任意环境都可作为变更集来源或目标。每个环境需要名称、本地目录、E-cology 服务器地址、登录名和密码。

环境目录位于工作区根目录，只允许英文字母、数字和下划线，创建后不可修改；`common` 和 `promotion` 是保留名称。切换环境只会切换活动源码目录及其同步状态，不会复制或覆盖文件。

```text
workspace/
├─ dev_env/                         # 环境源码
├─ prod_env/
└─ .ecode-local/
   ├─ environments.json             # 环境配置
   ├─ dev_env/                      # 清单、快照、冲突、恢复和项目知识
   ├─ prod_env/
   ├─ common/ecode-ai/              # 公共 API、组件知识、Skill 和 CLI
   └─ promotion/                    # 推送、变更集和应用记录
```

`.ecode-local/` 可能包含源码快照，应加入版本库忽略规则。密码和 Cookie 按环境 ID 保存在 VS Code `SecretStorage`。

删除环境会永久删除对应源码目录、`.ecode-local/<环境目录>/` 和本机凭据；远端代码、公共推送记录和变更集不会被修改。最后一个环境不能删除。

## 同步流程

### 建立基线

配置环境并通过连接测试后，执行 `Ecode: 全量拉取`。全量拉取会下载远端源码、建立同步基线，并刷新该环境的代码智能资料。

新环境必须先完成一次全量拉取。扩展不会把基线建立前的现有本地源码误报为新增，也不允许此时推送或应用变更集。

### 检查与推送

保存或删除本地文件后，侧边栏会自动刷新；也可执行 `Ecode: 刷新本地与远端变更` 主动扫描两端。该命令只更新状态，不会把远端内容写入本地。

确认差异后执行 `Ecode: 选择并推送`。选择文件后会直接开始推送，记录默认以当前时间命名，可在侧边栏重命名或删除。删除推送记录不会修改任何源码。

推送会依次检查：

- 远端内容是否仍与同步基线一致；
- JavaScript/JSX 能否按 Babel 7.5.5 编译；
- 内容能否用 GBK 表示；
- 写入后的远端内容是否与本地一致。

更新请求超时或返回 5xx 时，扩展会先回读远端再判断实际结果。若相同内容已经写入，可再次确认以补齐本地基线和推送记录，不会重复上传。

### 推送记录与回退

展开环境下的“推送记录”可查看文件差异、重命名或删除记录，并对单个文件执行本地回退。回退只修改本地源码，不修改远端或同步基线；如果文件在推送后又被编辑，扩展不会覆盖新编辑。

## 冲突与恢复

当本地和远端都偏离同步基线时，扩展会记录冲突而不是覆盖任一侧。可选择：

- 接受最新远端内容；
- 手工合并文件后，确认保留本地内容。

远端删除而本地有修改时，可接受远端删除或保留本地并转为待推送文件。恢复副本保存在 `.ecode-local/<环境目录>/recovery/`。

Ecode 可能返回无法唯一判断的重名节点。扩展会隔离存在歧义的文件或目录子树，保留已有本地文件，并继续拉取其他安全内容；推送和变更集不会写入歧义路径。可在 Ecode 输出日志中查看冲突路径和脱敏后的候选节点 ID。

## 跨环境变更集

变更集由一次或多次成功推送记录创建，不依赖 Git，也不预先绑定目标环境。同一文件的多次推送会折叠为最终净变化：新增或修改使用最终快照，删除则删除目标环境中的同路径文件。

应用前会整体检查不安全路径、文件与目录同名、父路径是文件以及 GBK 不兼容等问题。覆盖或删除前会分别保存目标环境的远端和本地内容，成功写入后更新目标源码、同步基线和应用记录。

实际写入的文件会同时形成目标环境的一条推送记录。重复应用会跳过已经收敛的文件，并继续处理上次未完成的部分。删除变更集只删除记录，不会删除推送记录、回退代码或修改远端。

## 编码与兼容性

Ecode 源码按 GBK 写入远端。GBK 不支持的字符需要改用 ASCII 转义，例如将 `›`（U+203A）写为 `"\u203A"`；普通 ASCII `>` 不受影响。

扩展支持 VS Code 1.93+ 和泛微 E-cology 9 Ecode。同步面向文本源码，不支持二进制资源；内置 API、字段和组件知识应以实际 Ecode 环境及官方文档为准。

## AI Coding 支持

首个环境配置成功后，扩展会在 `.ecode-local/` 中生成公共知识、环境知识、`ecode-local` Skill 和 Agent CLI，并维护根目录 `AGENTS.md` 中的入口。移除后可从 Ecode 侧边栏的更多操作中重新启用。

Agent 应读取生成的 Skill，并通过其中的 CLI 使用扩展功能，不应直接修改 `.ecode-local/` 内部状态。拉取无需确认；推送、环境切换、删除、回退、冲突处理和变更集应用等受保护操作，必须先取得当前任务的明确授权。

需要 VS Code 表单或选择器的 Agent 操作会返回 `pending`。用户在 VS Code 中完成或取消交互后，Agent 应使用原请求 ID 续查，不能创建重复请求。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 环境无法连接或登录信息失效 | 重新执行 `Ecode: 配置当前环境`，核对服务器地址和登录信息并完成连接测试；详细错误可在 VS Code“输出”面板的 `Ecode` 通道查看。 |
| 不能推送或应用变更集 | 确认当前环境已经成功完成一次全量拉取，并检查侧边栏是否存在未解决冲突。 |
| 本地和远端同时发生修改 | 先查看差异；需要远端版本时选择接受远端，需要保留合并结果时先手工编辑，再确认保留本地。 |
| 提示字符无法用 GBK 表示 | 将不兼容字符替换为 GBK 字符，或在字符串中使用 ASCII Unicode 转义后重新检查。 |
| 路径被标记为远端歧义或不支持 | 在 `Ecode` 输出通道查看冲突路径和脱敏节点 ID，并在远端整理重名节点；不要尝试绕过检查强制写入。 |
| 变更集只成功了一部分 | 根据错误修复网络、权限、冲突或编码问题，然后重新应用同一变更集；已成功文件会被跳过。 |
| 需要找回被覆盖或删除前的内容 | 查看 `.ecode-local/<环境目录>/recovery/`；推送记录中的单文件回退仅恢复本地内容，不会修改远端。 |
